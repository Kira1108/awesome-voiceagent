DESIGN SPEC · v0.1 · 2026-07 · OPEN SOURCE PROPOSAL
Voice Agent Framework · Design Report

A conversation runtime that treats the user and the agent as two signals to schedule.

LiveKit Agents perfected the worker infrastructure. Pipecat perfected the frame pipeline. Cadence proposes the missing third layer: a conversation scheduler — turn-taking, interruption, speculation, and latency budgets as first-class, testable runtime primitives, independent of any transport.

Session trace · turn 41 → 42 · barge-in event USER AGENT SPECULATIVE
Every session emits this trace. The runtime speculated during the user's pause, committed when end-of-utterance confidence crossed threshold, and cancelled the entire downstream graph in 118ms when the user barged in. All four decisions are replayable events, not side effects buried in callbacks.
01 · Thesis

The hard problem is no longer moving audio. It is deciding, every 20ms, who owns the floor.

Transport is a solved problem — WebRTC SFUs, SIP trunks, and WebSocket streams are commodity. Model quality is a vendor race you don't have to run. What remains genuinely unsolved in open source is the conversation layer: the logic that decides when the user has finished speaking, when to start responding, what to throw away on interruption, and how to hit a latency budget while doing all of it.

Today that logic lives in scattered VAD callbacks and ad-hoc task cancellation inside every team's fork. Cadence makes it the product.

Borrowed from LiveKit

Supervised session actors

Every conversation is an isolated, supervised actor with its own lifecycle, restart policy, and resource guard — a failed tool call or provider timeout can never take down a worker.

Borrowed from Pipecat

Typed event flow

All data — audio chunks, transcript deltas, tokens, tool calls, control signals — are typed events with turn epochs and timestamps, flowing through an explicit graph.

The innovation

Conversation scheduler

A deterministic core that owns turn-taking, speculation, cancellation, and latency budgets — and can be replayed, unit-tested, and simulated offline like any state machine.

02 · Architecture

Three planes, one contract: everything is a turn-stamped event.

Cadence separates concerns into a media plane, a conversation plane, and an operations plane. The planes communicate only through typed events carrying a monotonic turn_id epoch — the mechanism that makes interruption race-free: any event stamped with a stale epoch is dropped at every node, so "half a word escaping after barge-in" becomes structurally impossible.

Media Plane
Transport adapters & audio I/O

Jitter buffers, resampling, echo-cancelled capture. Transports are pluggable — LiveKit is an adapter here, not a dependency.

# An agent is a graph + a budget + policies. The runtime owns everything else.
agent = cadence.Agent(
    graph = STT(deepgram) >> LLM(gpt, tools=[book_meeting]) >> TTS(elevenlabs),
    turn_policy  = SemanticEOU(min_silence=240ms, confidence=0.7),
    budget       = LatencyBudget(first_audio=600ms, fallback=LLM(small_model)),
    speculation  = Speculate(on=eou.predicted, commit=eou.confirmed),
    policies     = [RedactPII(), ToolPermissions(scope="calendar:write")],
)

cadence.serve(agent, transport=LiveKitTransport(room), replay=True)
03 · Turn Coordinator

Turn-taking as a five-state machine, not a VAD callback.

The coordinator fuses three signals — acoustic VAD, streaming ASR stability, and a lightweight semantic end-of-utterance model — into one arbiter that owns the floor. Every transition is an event in the replay log, so "why did the agent talk over the caller at 00:41?" has a precise, inspectable answer.

DELIBERATING is the novel state: the graph is already running speculatively, but no audio is committed. If the user resumes speaking, retraction costs nothing audible.

Speculative execution, made safe by epochs

When end-of-utterance probability crosses the speculation threshold (but not yet the commit threshold), the runtime starts LLM inference on the partial transcript and pre-warms TTS. Two outcomes:

EOU confirmed · ~70–80% of turns

Speculation pays off

First audio ships 300–500ms earlier than a strictly sequential pipeline, because inference overlapped the user's trailing silence.

User resumes · the rest

Retraction is free

Epoch increments; every in-flight event with the old turn_id is dropped at each node. Cost: a few wasted tokens. Never a wrong word spoken aloud.

04 · Latency Budgets

Declare the budget. The scheduler spends it.

Instead of hand-tuning buffer sizes, developers declare an end-to-end target such as first_audio < 600ms. The scheduler tracks remaining budget per turn and makes runtime decisions: shrink endpointing silence, switch to the fallback model, start TTS at the first sentence boundary, or skip an optional enrichment step. Budget spend is attributed per stage in every trace.

05 · Determinism & Observability

Every conversation is an event log you can replay in CI.

The conversation plane is event-sourced: decisions (state transitions, speculation starts, cancellations, budget reallocations) and their inputs are appended to a compact log — raw audio optional and policy-gated. That single design choice buys three capabilities no current framework offers together:

Debug

Time-travel replay

Load a production session log locally and step through the coordinator's decisions frame by frame. The FSM is pure, so replay is bit-exact.

Test

Regression conversations

Pin real barge-in incidents as fixtures. CI replays them against every PR: "the agent must yield within 150ms on fixture #23" is an assertion, not a hope.

Load

Synthetic session simulator

Run thousands of scripted callers — packet loss, mid-word interruptions, slow tools, provider 500s — before any human talks to the agent.

Traces are standard OpenTelemetry: one span per turn, child spans per stage, with budget attribution attached — so latency dashboards work in whatever stack you already run.

06 · Policy Plane

Compliance as configuration, not code review.

Voice agents ship into regulated surfaces — telephony, healthcare, finance. Cadence centralizes the controls teams otherwise rebuild ad hoc: streaming PII redaction before transcripts leave the session actor, tool permission scopes checked at call time, recording consent gates on the replay log, per-tenant rate and spend quotas, and data-residency pinning for provider routing. Policies are declarative, versioned, and evaluated inside the conversation plane so they apply uniformly to every graph.

08 · Roadmap

Three releases to production credibility.

Phase 1 · Weeks 1–8 · “It converses”

Deterministic core

  • Python runtime: typed events, turn epochs, execution graph with backpressure + cancellation
  • Five-state turn coordinator (VAD + ASR stability + semantic EOU)
  • WebSocket + local-mic transports; 2 providers each for STT/LLM/TTS
  • Event log + offline replay CLI from day one
Phase 2 · Weeks 9–18 · “It performs”

Speculation & budgets

  • Speculative execution with commit/retract; latency-budget scheduler with fallback routing
  • LiveKit + SIP transport adapters; session actor supervision
  • OpenTelemetry spans with per-stage budget attribution
  • Benchmark CLI: publish reproducible first-audio latency numbers vs. baselines
Phase 3 · Weeks 19–30 · “It ships”

Operations & trust

  • Synthetic caller simulator (packet loss, barge-in storms, provider chaos)
  • Policy plane: PII redaction, tool scopes, consent gates, tenant quotas
  • Replay-fixture regression suite as a public conformance benchmark
  • Reference deployment: Helm chart, autoscaling guide, 1.0 stability contract

What to measure from week one

First-audio P50/P95 · barge-in yield time P95 (<150ms) · speculation hit rate · wasted-token ratio · sessions per core · replay determinism (100%). These six numbers are the project's public scoreboard — publish them in the README every release.
