CADENCE_RUNTIME
设计规格书 · v0.1 · 2026-07 · 开源项目提案
语音智能体框架 · 设计报告

一个把用户和智能体视为两路待调度信号的对话运行时。

LiveKit Agents 打磨出了极致的工作进程基础设施，Pipecat 打磨出了极致的帧式流水线。Cadence 提出两者都缺失的第三层：一个对话调度器 —— 将话轮切换、打断、投机执行与延迟预算作为一等公民、可测试的运行时原语，并与任何传输层解耦。

Session trace · turn 41 → 42 · barge-in event USER AGENT SPECULATIVE
每个会话都会产生这样一条轨迹。运行时在用户停顿期间进行了投机计算，在句尾（EOU）置信度越过阈值时提交输出，并在用户抢话时于 118ms 内取消了整个下游执行图。这四个决策全部是可回放的事件，而不是埋在回调里的副作用。
01 · 核心论点

难题早已不是搬运音频，而是每 20ms 判定一次：话语权归谁。

传输层是已解决的问题 —— WebRTC SFU、SIP 中继、WebSocket 流都已商品化。模型质量是厂商之间的军备竞赛，你不必亲自下场。开源世界里真正悬而未决的，是对话层：判断用户何时说完、何时开始回应、被打断时该丢弃什么、以及在做这一切的同时如何守住延迟预算的那套逻辑。

今天，这套逻辑散落在各团队自己 fork 出来的 VAD 回调和临时任务取消代码里。Cadence 把它变成产品本身。

借鉴自 LiveKit

受监督的会话 Actor

每个对话都是一个隔离的、受监督的 Actor，拥有独立的生命周期、重启策略和资源守护 —— 一次失败的工具调用或供应商超时，永远不可能拖垮整个 Worker。

借鉴自 Pipecat

类型化事件流

所有数据 —— 音频块、转写增量、Token、工具调用、控制信号 —— 都是带话轮纪元（turn epoch）和时间戳的类型化事件，在一张显式的图中流动。

真正的创新

对话调度器

一个确定性内核，全权负责话轮切换、投机执行、取消和延迟预算 —— 并且可以像任何状态机一样被回放、单元测试和离线仿真。

02 · 架构

三个平面，一份契约：一切皆为带话轮戳的事件。

Cadence 将关注点分离为媒体平面、对话平面和运维平面。三个平面之间只通过携带单调递增 turn_id 纪元的类型化事件通信 —— 正是这个机制让打断变得无竞态：任何携带过期纪元的事件都会在每个节点被直接丢弃，"抢话之后还蹦出半个字" 在结构上不可能发生。

Media Plane
传输适配器与音频 I/O

抖动缓冲、重采样、回声消除采集。传输层完全可插拔 —— LiveKit 在这里只是一个适配器，而不是依赖。

03 · 话轮协调器

话轮切换是一个五状态机，而不是一个 VAD 回调。

协调器将三路信号 —— 声学 VAD、流式 ASR 稳定度、以及一个轻量级语义句尾（EOU）模型 —— 融合为一个掌握话语权的仲裁者。每一次状态迁移都是回放日志中的一个事件，所以"智能体为什么在 00:41 抢了来电者的话？"有精确、可审查的答案。

DELIBERATING（酝酿中）是新颖的一环：执行图已经在投机运行，但没有任何音频被提交。如果用户继续说话，撤回不会付出任何可听见的代价。

投机执行，由纪元机制保证安全

当句尾（EOU）概率越过投机阈值（但尚未达到提交阈值）时，运行时就基于部分转写启动 LLM 推理，并预热 TTS。两种结局：

EOU 确认 · 约 70–80% 的话轮

投机获得回报

首帧音频比严格串行的流水线提前 300–500ms 送出，因为推理与用户的尾部静音重叠进行。

用户继续说话 · 其余情形

撤回零成本

纪元自增；所有携带旧 turn_id 的在途事件在每个节点被丢弃。代价：浪费几个 Token。绝不会有一个错误的字被说出口。

04 · 延迟预算

你声明预算，调度器负责花。

开发者不再手工调各处缓冲区大小，而是声明一个端到端目标，例如 first_audio < 600ms。调度器逐话轮跟踪剩余预算并在运行时做决策：收紧端点静音判定、切换到降级模型、在第一个句子边界就启动 TTS、或跳过某个可选的增强步骤。每条链路追踪中都会按阶段归因预算的消耗。

05 · 确定性与可观测性

每一通对话都是一份可以在 CI 里回放的事件日志。

对话平面采用事件溯源：所有决策（状态迁移、投机启动、取消、预算重分配）及其输入都被追加到一份紧凑的日志中 —— 原始音频可选且受策略门控。这一个设计决定，同时买到了当前任何框架都无法兼得的三种能力：

调试

时间旅行回放

把生产环境的会话日志加载到本地，逐帧单步审视协调器的每个决策。状态机是纯函数，所以回放是比特级精确的。

测试

回归对话集

把真实的抢话事故固化为测试夹具。CI 对每个 PR 回放它们："智能体必须在夹具 #23 上于 150ms 内让出话语权" 是一条断言，而不是一个愿望。

压测

合成会话仿真器

在任何真人和智能体对话之前，先跑几千个脚本化的模拟来电者 —— 丢包、词中打断、慢工具、供应商 500 错误。

链路追踪采用标准 OpenTelemetry：每个话轮一个 Span，每个阶段一个子 Span，并附带预算归因 —— 你现有技术栈里的延迟看板可以直接使用。

06 · 策略平面

合规是配置项，而不是代码评审。

语音智能体会落地在强监管场景 —— 电话、医疗、金融。Cadence 将各团队原本各自重复造轮子的管控能力集中起来：转写离开会话 Actor 之前的流式 PII 脱敏、调用时校验的工具权限范围、作用于回放日志的录音同意门控、按租户的速率与费用配额，以及供应商路由的数据驻留锁定。策略是声明式的、有版本的，并在对话平面内部求值，因此对每一张执行图统一生效。

09 · 认知层

两个大脑，一个声音：快速应答者在前，后台思考者在后。

单一模型无法既即时又深刻。认知层把智能体拆成一个 Responder（应答者） —— 掌握话语权的小型快速对话模型，和一个 Thinker（思考者） —— 异步处理工具、RAG 和多步规划的大型推理模型。这个模式已被生产环境验证：OpenAI 的 Realtime 系列用一个 mini 语音模型搭配被委派的推理模型，Salesforce 的 VoiceAgentRAG 则将其形式化为 "Fast Talker / Slow Thinker"，实现了 75% 的预取命中率和缓存命中时 316 倍的检索加速。

Cognition dataflow · responder / blackboard / thinker FOREGROUND BACKGROUND SHARED STATE
Thinker 从不发声，Responder 从不检索。二者只在黑板（blackboard）相遇 —— 一份有版本、带话轮纪元戳的会话状态。因为每条记录都携带 turn_id，一次抢话就能用取消过期音频的同一套纪元机制，把过期的思考一并作废。

缓存优先，而非委派优先

按需委派是兜底路径，不是主路径。Thinker 持续读取实时转写，预测接下来最可能出现的两三个信息需求，并在用户话音未落之前就把答案预取进黑板的语义缓存。大多数话轮里，Responder 用手头已有的状态即可作答 —— 只有缓存未命中时才发生委派。

层级路径延迟处理内容
T0 · 反射仅 Responder<300ms应答确认、寒暄、复述确认、话轮管理
T1 · 缓存命中Responder + 黑板读取<500msThinker 已预取的事实 —— 常态情形（目标命中率 ≥70%）
T2 · 延迟应答委派 → 时间桥接 → 重新切入1–10s缓存未命中、有副作用的工具、全新的多步推理

委派契约

Responder 输出的是结构化意图，绝不是寄希望于自由文本。路由由运行时完成 —— 而不是模型。一份硬性黑名单定义了 Responder 绝不允许凭自身权重回答的内容：价格、条款、账户事实、医疗论断。这些要么带着出处从黑板取得，要么被委派出去。

# Responder output is constrained: speak, delegate, or both.
class ResponderTurn:
    utterance: str                      # what to say now (may be a bridge)
    delegations: list[Delegate]        # tasks for the Thinker

class Delegate:
    kind: "rag" | "tool" | "reason"
    query: str
    urgency: "blocking" | "background"
    effectful: bool                    # True → requires confirm gate before execution

# Thinker output is structured — it never produces prose for the user.
class Conclusion:
    task_id: str
    turn_id: int                       # stale epochs dropped on arrival
    answer: dict                       # structured facts + provenance
    speakable: str                     # one-line summary the Responder may voice
    confidence: float

时间桥接：Thinker 工作时，用户听到什么

剩余 < 800ms

静默

一个自然的停顿。不加填充语 —— 人类不会给亚秒级的等待配旁白，智能体也不该。

0.8 – 3s

情境化应答

"我帮您调一下订单" —— 从一个多样化、随上下文变化的语料集中采样，绝不循环播放同一句套话。流式返回的部分事实可以边到边说。

> 3s

并行话题 + 重新切入

Responder 在另一条有用的线索上推进对话（核对信息、收集下一个槽位），等结论落地后再切回来："好——关于那笔退款……"。填充语预算：两次，之后就坦诚说明延迟。

一致性规则

异步结果在对话中途到达，会产生两类必须由运行时兜住的风险：

风险 1 · 前后矛盾

已说断言审计

Responder 说出的每一条事实性话语都会记入 spoken_claims。当 Thinker 的结论与先前断言相矛盾时，运行时会标记冲突，Responder 必须在下一话轮口头更正 —— 让编造被抓住，而不是被掩埋。

风险 2 · 过期工作

纪元作用域任务

Thinker 的任务携带其诞生时的 turn_id。抢话或话题切换时，纯任务（RAG 查询）被取消或降级为后台事实；有副作用的任务绝不自动取消 —— 副作用只有在显式确认门之后才会执行。

需要度量的指标

缓存命中率（目标 ≥70%）· T0/T1/T2 话轮分布 · 桥接到结论的延迟 P95 · 更正率（每 100 话轮的矛盾次数）· 预取浪费率。这些指标并入 §08 的运行时记分牌。
