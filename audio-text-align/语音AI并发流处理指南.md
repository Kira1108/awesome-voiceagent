# 极致低延迟语音 AI 架构：VAD 与 STT 并发流处理指南

在构建高性能语音助手（如 LiveKit Agents 或 Pipecat）时，**延迟（Latency）** 是决定用户体验的核心指标。本文档详细说明了如何通过“并发无阻塞”模式同时处理 VAD（语音活跃检测）和 STT（语音识别），以实现极致的响应速度。

---

## 1. 核心设计理念：并发分发 (Fan-out)

### 传统串行模式（低效）
音频 -> VAD 判断 -> (若有人声) -> 建立 STT 连接 -> 发送音频。
*   **缺点**：VAD 判断需要时间（约 100-200ms），STT 建连需要时间（约 200-500ms），导致首字识别丢失和明显的响应滞后。

### 并发流式模式（最优）
音频进入后，**立即且同时**分发给 VAD 和 STT 任务，互不阻塞。
*   **优点**：
    *   **零启动延迟**：用户开口瞬间，STT 流已处于“热”状态，无需等待建连。
    *   **完整性**：STT 能够接收到 VAD 判定前的微量“预热”音频，确保第一个字不被截断。
    *   **异步解耦**：VAD 在本地 CPU 跑，STT 在网络 IO 跑，资源利用率最高。

---

## 2. 系统架构逻辑

1.  **音频采集层**：以固定频率（如 20ms 一帧）推送 PCM 音频块。
2.  **分发层 (Dispatcher)**：通过异步队列或通道，将同一帧音频的副本同时推给 VAD 和 STT。
3.  **处理层**：
    *   **VAD 任务**：实时计算活跃度，仅输出状态事件（`UserStartedSpeaking`, `UserStoppedSpeaking`）。
    *   **STT 任务**：实时上传音频，持续接收转录片段（Interim Transcripts）。
4.  **逻辑门控层 (Orchestrator)**：
    *   **关键策略**：STT 始终在转录，但只有当 VAD 状态为 `Speaking == True` 时，转录文字才会被累加并发送给 LLM。
    *   **静音过滤**：VAD 判定为静音时的 STT 结果（可能是背景噪音或呼吸声）将被直接丢弃。

## 3. 源代码示例 (Python Asyncio)

以下是一个简化版的实现逻辑，展示了如何并发分发音频帧：

```python
import asyncio
import time

class VoiceOrchestrator:
    def __init__(self):
        self.is_speaking = False
        self.transcript_buffer = []

    async def vad_task(self, audio_queue):
        """本地 VAD 任务：负责判断‘什么时候说话’"""
        while True:
            frame = await audio_queue.get()
            # 模拟 VAD 计算延迟
            is_active = self.simulate_vad_logic(frame)
            
            if is_active and not self.is_speaking:
                print(f"[{time.time():.2f}] VAD: 检测到人声开始")
                self.is_speaking = True
            elif not is_active and self.is_speaking:
                print(f"[{time.time():.2f}] VAD: 检测到静音结束")
                self.is_speaking = False
                await self.commit_to_llm()

    async def stt_task(self, audio_queue):
        """流式 STT 任务：负责识别‘说了什么’"""
        while True:
            frame = await audio_queue.get()
            # 模拟发送到云端并获取中间结果
            text = await self.simulate_stt_cloud_request(frame)
            
            if text and self.is_speaking:
                # 只有 VAD 说在说话，我们才记录文本
                print(f"[{time.time():.2f}] STT (有效): {text}")
                self.transcript_buffer.append(text)
            elif text:
                # VAD 没触发时的识别结果视为噪音，丢弃
                print(f"[{time.time():.2f}] STT (丢弃噪音): {text}")

    async def main_loop(self):
        # 创建两个独立的队列，实现 Fan-out
        vad_queue = asyncio.Queue()
        stt_queue = asyncio.Queue()
        
        # 并发启动任务
        tasks = [
            asyncio.create_task(self.vad_task(vad_queue)),
            asyncio.create_task(self.stt_task(stt_queue))
        ]
        
        # 模拟音频采集流
        for _ in range(100):
            audio_frame = b"\x00" * 640 # 模拟 20ms 音频
            # 并发分发，无阻塞
            vad_queue.put_nowait(audio_frame)
            stt_queue.put_nowait(audio_frame)
            await asyncio.sleep(0.02)

    async def commit_to_llm(self):
        full_text = "".join(self.transcript_buffer)
        if full_text:
            print(f"--- 提交给 LLM: {full_text} ---")
        self.transcript_buffer.clear()

    def simulate_vad_logic(self, frame): return True # 模拟逻辑
    async def simulate_stt_cloud_request(self, frame): 
        await asyncio.sleep(0.01)
        return "你好" if time.time() % 2 > 1 else ""

if __name__ == "__main__":
    orchestrator = VoiceOrchestrator()
    asyncio.run(orchestrator.main_loop())
```

## 4. 极致优化的建议

1.  **Lookback Buffer (回溯缓冲)**：在 VAD 触发前的 200ms 音频应始终保留在 STT 的发送缓冲区中，防止丢字。
2.  **UDP/WebSocket 预连接**：在会话开始时即建立 STT WebSocket 链路，保持心跳，避免临时建连。
3.  **本地/边缘 VAD**：尽量在最靠近音频源的地方（如浏览器端或边缘节点）跑 VAD，以最快速度触发打断逻辑。
4.  **端点延迟 (Endpointing)**：不要只依赖 VAD 判定结束，应结合 STT 返回的“最终结果”标记和 LLM 对语义完整性的判断。
